## 为什么改与明确取舍

当前240样本在既定单卡/双卡、micro-batch1、累积4的路径均能组成完整累积组。可信的完整组正常数值对照直接服务于当前训练；不足组边界、跨环境异常和成套故障矩阵的投入收益较低，按用户要求延期。不能把这个取舍解释为任意样本量的尾组都正确。

| 项目 | 当前安排 | 重新需要验证的条件 |
| --- | --- | --- |
| 配对/尺度、输入映射、完整组累积、实际更新与有限性 | 保留最小正常验证，复用已有有效证据 | 当前路径失败时针对性定位 |
| 尾组/末尾小batch逐窗口对照 | 延期，不列本轮门槛 | 样本数、卡数、batch或采样改变导致不足组 |
| 四类故障与逐个健康对照 | 取消本轮开发要求 | 实际发现难以定位的当前路径错误时按需补最小用例 |
| buffer产品拒绝路径提取/变异验证 | 延期；本轮去掉测试自证拒绝，不改正确摘要或生产比较 | 实际DDP问题、buffer结构变化，或独立安排该验证 |
| Windows CPU DDP/libuv/Gloo | 默认跳过，不排环境 | 确需该平台CPU多进程时另行处理 |
| GPU运行 | 先复用小夹具，再用正式配置/真实数据有限更新 | 资源不足时去目标GPU，不回到扩充CPU测试 |
| 正式长训练、采样/指标、完整last/恢复 | 后续按实验主线推进，本次不接入 | GPU短程链路证据具备后安排下一任务 |

数值正常对照仍不能放宽容差掩盖差异。loss短程波动不自动代表错误，也不强制2步下降。正式配置OOM只证明该设备/配置资源不足，不冒称训练成功；单GPU通过也不冒称双4090通过。预期节省测试投入并更快获得GPU证据，尚无实测耗时节省或训练效果。
