## 网络选择与初始化

首版使用 `UNetModelSwin`，从头训练，不加载图像预训练权重。`UNetModel`、`UNetModelConv` 仅为效果不理想时的后续备选，不要求首版同时训练三个网络；备选也从头训练。

当前三个网络均在 forward 内拼接状态和条件。若后续启用备选网络，同尺寸单通道任务的 `UNetModel`、`UNetModelConv` 应配置 `in_channels=2`、`out_channels=1`；Swin 应配置 `in_channels=1`、`out_channels=1`，不能机械复用同一 `in_channels` 数值。

后续比较时共用数据、尺度、扩散、loss 和评价口径，并记录实际参数量和计算量；相同通道宽度不表示相同容量。道/时间轴的异形卷积、矩形窗口或不同轴下采样留作可选适配。

## 网络基准

官方配置基准：[NeurIPS 会议版 realsr_swinunet_realesrgan256.yaml](https://github.com/zsyOAOA/ResShift/blob/master/configs/realsr_swinunet_realesrgan256.yaml)。优先沿用其去噪网络设置；扩散日程已另行确定优先沿用该配置，见 [扩散配置](diffusion.md)。不将图像超分辨率的数据处理、VAE、loss、学习率、训练步数或 batch size 自动照搬为 DAS 任务决策。

| 参数 | 第一版基准 |
| --- | --- |
| 尺寸与注意力标记 | 若沿用现有标量控制逻辑，显式配置 `image_size=128`、`attention_resolutions=[128,64,32,16]`；真实输入尺寸另行表达为 `(128,4096)`，不将标量直接替换为元组 |
| 同尺寸条件分支 | 显式配置 `lq_size=image_size=128`、`cond_lq=True`、`cond_mask=False`，构造后检查 `feature_extractor` 为 `Identity`；扩散的 `sf=1` 不会自动设置 `lq_size` |
| 输入输出通道 | `in_channels=1`、`out_channels=1`；同尺寸条件在 forward 内拼接为 `[B,2,H,W]`，输出 `[B,1,H,W]` |
| `model_channels` | 160 |
| `channel_mult` | `[1,2,2,4]`，各层特征通道为 160、320、320、640 |
| `num_res_blocks` | `[2,2,2,2]` |
| Swin 位置 | 四个层级的编码器、解码器均保留当前实现的 Swin 插入位置，保留中间 Swin 模块；不是在每个残差块后都插入 Swin |
| `swin_embed_dim` | 192 |
| 注意力头 | 沿用 `num_head_channels=32`，Swin 实际为 `192/32=6` 个头 |
| `swin_depth` | 2，交替使用普通窗口与移位窗口 |
| `window_size` | 8，即 `8×8` 方形窗口；移位块沿两个轴各移动 4 格 |
| `mlp_ratio` | 4 |
| 其他网络设置 | 沿用 `dropout=0`、`conv_resample=True`、`dims=2`、`use_scale_shift_norm=True`、`resblock_updown=False`；BF16 AMP 不通过旧版 `use_fp16=True` 实现 |
| 任务接口改动 | 在波场空间执行扩散，单通道输入输出、同尺寸带噪条件，不增加条件 mask；不使用外部自编码器，不加载图像预训练权重 |

整段输入经过三级下采样后，空间尺寸依次为 `128×4096 → 64×2048 → 32×1024 → 16×512`，均能被 8 整除，因此这组尺寸不需要为了窗口整除而补边。Swin 的 U-Net 调用使用 `patch_size=1`，只在内部投影嵌入通道；整个 Swin 模块前后空间尺寸和主干通道数不变。

当前 `image_size` 同时参与标量尺寸标记和注意力层选择，`BasicLayer` 的名义尺寸又被当作正方形。适配时需要区分真实逐层 `(H,W)` 与注意力层级或下采样倍率，不能仅把 `image_size` 改成元组而保留原有标量运算。同尺寸条件分支应保持 `Identity`，不对带噪波场额外降采样。

Swin 掩码区域索引、窗口内 token 顺序和非移位分支已在 R001 修复并通过局部审阅，具体证据及同步状态见 [注意力代码修正](code-fixes/swin-attention.md)。验收包含具体 token 对和独立完整参考，不只检查 shape 或屏蔽数量；U-Net 的逐层真实尺寸贯通和整网运行验证仍未完成。

## 矩形尺寸与注意力验收

本节的 U-Net 矩形尺寸贯通仍是拟实施方案；注意力 mask、分支及相关尺寸类型的局部修复已经完成。当前完整输入尺寸满足窗口与上下采样约束；应区分局部注意力修复、整网尺寸传递，以及尚未发现必须重写的跳跃连接和窗口还原实现。

### 当前尺寸传递与拟修正方式

当前 `UNetModelSwin` 使用标量 `image_size` 初始化 `ds`，同时用 `ds in attention_resolutions` 决定注意力位置，并将 `img_size=ds` 传入 `BasicLayer`。`PatchEmbed` 再把这个标量转换为正方形名义尺寸。

若 `image_size=128`、完整输入为 `128×4096`，各层情况如下：

| 层级 | 当前传给 Swin 的名义尺寸 | 真实特征尺寸，也是修正后应传递的名义尺寸 |
| --- | --- | --- |
| 第一层 | `128×128` | `128×4096` |
| 第二层 | `64×64` | `64×2048` |
| 第三层 | `32×32` | `32×1024` |
| 第四层与中间模块 | `16×16` | `16×512` |

这不代表真实张量被变成了正方形：卷积与窗口 forward 仍使用真实 shape，Swin 也有实际尺寸不匹配时动态生成掩码的路径。因此，当前情况不能笼统描述为“不支持矩形”或“需要把数据变成正方形”；问题在于名义尺寸不准确、掩码预计算与比较不可靠、注意力位置和真实尺寸混用。

拟采用的最小适配方式：

1. 单独表达真实输入 `(H,W)`，例如增加 `input_size=(128,4096)`；字段名为实施建议，核心是与原标量注意力位置配置分离，不能只把旧 `image_size` 替换为元组。
2. 按层级计算 `stage_hw=(H//2**level, W//2**level)`，编码器、中间模块、解码器中对应的 `BasicLayer` 均接收该层真实名义尺寸。
3. 保留官方基准的全部注意力插入位置。若沿用原标量控制逻辑，`image_size=128` 时各层标记为 `[128,64,32,16]`；不能不经换算照搬官方名义输入为 64 时的 `[64,32,16,8]`，否则会漏掉第一层。也可显式用层级控制，但不得静默改变旧参数的含义。
4. 显式设置 `lq_size=image_size=128`，同尺寸条件走 `Identity`，并在构造后检查该分支。核验扩散状态和 `lq` 的空间尺寸一致，不因修改尺寸配置而误走带噪条件下采样分支；不能依赖 `lq_size=256` 的默认值。
5. 统一名义尺寸与实际尺寸的比较类型，例如统一成 `(H,W)` 元组。原实现的 `patches_resolution` 为列表、forward 尺寸为元组，数值相同仍不相等；R001 已完成本模块相关类型统一，但 U-Net 的逐层真实尺寸仍需另行传入。
6. 若 OOM 后改用裁窗，实际尺寸发生变化时使用与该尺寸匹配的移位掩码，不能复用完整波场的旧掩码。匹配时可复用已注册掩码；不匹配时按实际 shape 生成，并保证 device、dtype 与注意力计算一致。首版不要求引入复杂的多尺寸缓存。

### 移位掩码的正确性要求

掩码区域写入必须沿 NCHW 的两个空间轴进行，窗口展平顺序必须与实际特征保持一致；修复范围同时包含区域索引和窗口划分后多余的 `permute()`。具体错误代码、候选修改和小张量复现见 [代码修改说明](code-fixes/swin-attention.md)。

掩码应阻断循环移位造成的道轴首尾、时间轴首尾虚假邻接，同时保留正常窗口内及移位后合法的相邻区域交流。该修正改变的是注意力允许建立的关联，不改变输入输出 shape、窗口大小、窗口数量、网络参数量或层级布置；保留已有窗口划分和还原函数。

### 非移位与移位分支分开处理

R001 已统一名义／实际尺寸类型，并按是否移位先分支：非移位块固定使用 `mask=None`，移位块才生成或复用对应尺寸掩码。原代码问题及其触发条件保留在 [代码修改说明](code-fixes/swin-attention.md)，不将已修复的 `None.to()` 缺陷描述为当前错误。

拟采用以下控制逻辑，具体辅助函数名在实施时确定：

```python
if self.shift_size == 0:
    mask = None
elif actual_hw == nominal_hw:
    mask = self.attn_mask.to(device=x.device, dtype=x.dtype)
else:
    mask = self.calculate_mask(actual_hw).to(device=x.device, dtype=x.dtype)

attn_windows = self.attn(x_windows, mask=mask)
```

仅在移位分支生成或复用边界掩码；不改普通窗口与移位窗口交替的原机制，不为此次修正额外引入因果注意力或新的窗口形状。

### 尺寸约束与需保留的结构

当前四级结构有三次双轴下采样。若所有层均保持 `8×8` 窗口且不补边，输入的道数、时间长度取 64 的整数倍，可同时满足逐层整除与窗口划分要求。完整 `128×4096` 以及备用候选 `128×2048`、`128×1024`、`128×512` 均满足；候选窗口长度尚未定案。

还需检查最深层最短边：当前代码在名义最短边不大于窗口时会关闭移位、必要时缩窗。以上尺寸的最深层最短边均为 16，不触发此行为；不能仅检查“能被 64 整除”，就默认任意小尺寸仍保留相同的移位行为。

- 入口校验输入及配对条件的轴顺序、尺寸一致性与各层整除约束；不合规尺寸应给出清晰错误，不自动拉伸或静默裁切来掩盖问题。
- 保留 `patch_size=1`、现有上下采样、跳跃连接与窗口划分/还原流程；不以这次正确性修正为由重写这些结构。
- 解码器每次拼接前，验证当前特征与对应 skip 特征的 `(H,W)` 相同，通道沿 `dim=1` 拼接；当前完整尺寸没有发现必须插值或裁边的理由。

### 小规模检查的证据范围与后续验收

2026-10-27 首次交叉审查通过真实函数的 CPU 小张量比较，确认原方案“仅修 NCHW 索引”的候选仍存在窗口内 token 顺序错误。因此，先前记录的 shape 和屏蔽数量相同、掩码改变 3072 个元素等结果只保留为不完整候选的诊断记录，不能作为修复正确的通过证据；完整对照及具体 token 对见 [代码修改说明](code-fixes/swin-attention.md)。该历史阶段候选只在内存比较、未改源码；后续 R001 已落盘并通过局部验收。

验收清单如下。R001 已覆盖四层完整矩形的窗口往返、具体 token／完整参考掩码和缓存／动态分支；裁窗方案未定，不据此宣称裁窗实验通过。完整 U-Net、检查点及训练项目仍待实施：

1. 对各层完整矩形尺寸及选用的裁窗尺寸检查窗口划分、还原的逐元素一致性。
2. 检查非移位分支确实传 `mask=None`；移位分支与独立参考掩码逐元素比较，并断言跨时间首尾、跨道轴首尾的具体 token 对被屏蔽，合法相邻 token 对被保留，不能只比较屏蔽数量。
3. 检查名义尺寸匹配、动态尺寸不匹配两条路径；同一真实尺寸下的掩码应一致，切换裁窗不能使用旧尺寸掩码。
4. 对完整 U-Net 记录各层 shape，核对全部 skip 拼接，确认输入 `[B,1,H,W]` 和条件各一通道、内部拼接两通道、输出 `[B,1,H,W]`。
5. 在 BF16 AMP 与梯度检查点配置下验证有限输出、有限梯度及检查点前后的一致性，并完成一次真实训练更新。目标双卡的显存和完整采样仍按[训练流程](training.md)与[实施验收](implementation.md)单独验收。
