## 1. 目标和推荐决定

将 `dev` 作为唯一日常开发与验收汇总分支，沿用其现有目录结构。先接收、保护服务器已推送的结果并核对完整性，再恢复真正的最新绘图修改，精确纳入服务器新增能力，最后整理旧分支和输出。避免同时维护两套相同训练代码，也避免再次通过切分支寻找“最新版本”。

完成后应满足：

1. 最新训练、评估、绘图代码都能从 `dev` 获取；日常运行文档只有一套推荐入口。
2. 简洁版绘图代码及测试已提交，不再仅存在 stash 中。
3. `test/code` 保留为按现有协作规则使用的实施分支，不再将多个分支都当作最新工作版本。
4. `codex/server-code` 退出独立开发，仅保留可追溯的服务器快照；后续服务器代码来自经过验收的 `dev`。
5. 普通工作目录不含 `.worktrees`、旧绘图副本、临时渲染脚本或散落的可视化备份。
6. 只在一个固定位置保留最新代码生成并验收的绘图结果；其他图像移入项目 `delete/`，由用户手动删除。
7. 数据、checkpoint、既有训练日志、审计结论及远端历史不因整理而丢失。

不在本次范围内：模型重构、重新训练、重新做全量数据审计、改写 Git 历史、强推、重建环境、自动清空 stash、自动删除用户结果。

- 如果新的代码不能可靠读取已有结果、checkpoint 或数据，暂停发布新入口，保留服务器快照，不通过修改正式数据绕过问题。
