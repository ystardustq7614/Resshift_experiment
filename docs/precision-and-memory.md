## 设备与精度约定

训练设备预算为两张 RTX 4090，每张 24 GB；取代此前按本机 RTX 5050 约 8 GB 的规划，不代表目标环境已验证。

| 因素 | 要求 | 状态 |
| --- | --- | --- |
| 训练精度 | BF16 AMP，保留必要的 FP32 参数、优化器状态与数值统计；不把所有数组或所有模块强制转换成 BF16 | 已确定，待实现与验证 |
| 梯度检查点 | 分别对卷积残差块和 Swin Transformer 块启用，均显式使用 `use_reentrant=False`、保留重算 RNG；不能仅开启现有 Swin 内部检查点开关。具体封装与反向一致性见 R005 记录 | R005 局部已验收，a60e625 已同步 dev 并复测；目标双卡／完整尺寸资源待验 |
| 环境与运行验证 | 核实目标双 RTX 4090 环境的 PyTorch/CUDA、timm、BF16 和分布式训练支持；优先完成 Swin 导入、前向、反向、优化器更新与完整采样验证 | 必须验证 |

磁盘 float16 与 BF16 AMP 是不同事项。两类检查点的实际封装见 [梯度检查点代码修改说明](code-fixes/gradient-checkpointing.md)。

## 静态容量估算及证据范围

以下核算采用已确定的直接波场训练与整段 `128×4096` 优先路线，不经过外部自编码器，沿用 [模型约定](model.md)网络基准。起测配置已确定为每卡 micro-batch=1、两张卡、梯度累积 4 次，有效 batch=8；整段训练的可运行性仍需实际验证，后续可依据实测调整。

使用本地实现进行 FakeTensor 形状与 autograd 保存张量核算；掩码修正和检查点封装仅用于独立估算过程，未写回项目模型源码，也未在双 4090 上执行真实训练。单通道适配后的网络参数量约为 118584941（1.186 亿）。

| 方式 | 前向结束时保存的非参数张量存储估计 | 对每卡 24 GB 的判断 |
| --- | --- | --- |
| FP32，不开梯度检查点 | 约 68.5 GiB | 超出预算 |
| BF16 AMP，不开梯度检查点 | 约 46.1 GiB | 超出预算 |
| BF16 AMP，仅 Swin 内部启用检查点 | 约 21.0 GiB | 加上模型状态、重算与其他开销后很可能超出 |
| BF16 AMP，残差块与 Swin 块分别启用检查点 | 约 5.7 GiB | 有可行性，峰值仍需实测 |

上述数值不是总显存或峰值。FP32 参数、梯度与 Adam/AdamW 两份状态按每参数 16 字节估算，另需约 1.77 GiB；首版不启用 EMA，不分配额外 EMA 权重（若后续启用 GPU FP32 EMA，再约需 0.44 GiB）。还要计入反向重算的临时张量、卷积工作区、通信缓冲、CUDA 与分配器开销。

当前选定方案先按每卡约 **15～22 GiB** 规划；这是基于保存张量与重算开销的工程估计，实际峰值可能超出，不能据此承诺单卡 batch=1 已经可运行。检查点降低保存激活的开销，但增加重算时间，不删减网络层级。

结合当前数据量和已确定起测配置，进一步区分以下开销。本次重新核对六个 NPY 文件头及文件大小，并进行字节数核算；沿用上表既有的激活存储估算，没有新增目标 GPU 峰值实测。

| 项目 | 大致用量 | 口径 |
| --- | --- | --- |
| 训练集 240 对，磁盘 float16 | 480 MiB | `train_x/train_y` 数据体总量，文件头开销忽略不计 |
| 全部 312 对，磁盘 float16 | 624 MiB | 含 36 对验证和 36 对测试，不需要整体搬到 GPU |
| 训练集全部展开为 float32 | 960 MiB | 仅作数据体容量对照；当前按 mmap 逐样本读取，不要求整体展开 |
| 每卡一次读取的 noisy/clean 对，float32 | 4 MiB | 两个 `[1,1,128,4096]` 张量；不含扩散中间量和网络特征 |
| 每卡 FP32 参数 | 约 0.442 GiB | 使用前述约 1.186 亿参数估计 |
| 每卡 FP32 梯度 | 约 0.442 GiB | 累积到同一组梯度缓冲，不为四轮分别保存四份梯度 |
| 每卡 Adam/AdamW 两份 FP32 状态 | 约 0.884 GiB | 仅作为优化器状态估算，优化器尚未最终选择 |
| 每卡前向结束保存的非参数张量 | 约 5.7 GiB | 沿用既有 BF16 AMP、两类模块分别检查点的静态估算，非总峰值 |
| 每卡训练总显存规划 | 约 15～22 GiB | 包含重算、临时张量、工作区与通信等余量的工程范围，非实测保证 |

模型、梯度、Adam 状态与上述保存张量的账面合计约 7.5 GiB，不能据此把训练峰值估成 7.5 GiB。额外峰值与 checkpoint 封装、注意力中间量、掩码、卷积算法和 DDP 配置有关；例如未与梯度共享存储的 DDP 梯度桶可能额外占约一份梯度大小，优化器临时量也需实测。首版已确定不用 EMA，不计额外 EMA 显存。

按四层真实矩形尺寸预计算且保持 FP32 时，九个移位块的固定掩码合计约 342 MiB/模型副本。该静态字节数不等于额外峰值，也不应在未核对既有估算口径时重复相加。固定掩码的持久化、恢复重建和 DDP buffer 同步策略须显式记录，不能只按参数量估计 checkpoint 或通信开销；代码接入注意事项见 [代码修改说明](code-fixes/rectangular-input.md)。

梯度累积须在每个 micro-step 完成前向和反向，再释放该轮计算图；不保留四份 loss 的计算图最后统一反向。按此实现，累积 4 次不会使激活显存乘以 4，但后续 micro-step 已有梯度缓冲常驻，峰值可能比第一轮稍高。若训练集按现有 240 对完整遍历、无额外重复采样，每卡每 epoch 处理 120 个 micro-step，总计约 30 次优化器更新。

因此当前数据量主要影响 epoch 长度与总训练时间，每卡显存主要由单个完整波场经过大网络时的中间特征决定。双卡合计约 30～44 GiB 只表示两张卡用量的相加，仍须分别满足每张 24 GB 卡的容量。整段若 OOM，按既定路线切换配对裁窗，不将调整累积次数当作解决单样本 OOM 的办法。

官方会议版去噪器的名义输入为 `64×64` 潜变量，完整波场的空间位置数是其 128 倍；不能照搬官方 batch size。训练集 240 个样本按需读取，不整体装入显存；单步显存主要由网络、输入尺寸与 micro-batch 决定。训练每样本抽取一个扩散时间步，不将完整采样链展开为训练计算图，因此不把显存简单乘以扩散步数。

## 墙钟时间估算

训练总时长在目标双 4090 完成吞吐实测前不作小时数承诺。可用 `9000*T_update + 31*T_full_val + 300*T_save` 加启动和其他开销估算；其中 T_update 必须包含双卡每卡 4 个 micro-step 的前向、反向、重算、同步及参数更新，T_full_val 是实际评估策略下的整套 36 对验证墙钟时间，T_save 是完整 checkpoint 写入耗时。若验证仅在一张卡执行，不能按两卡吞吐替它减半。
